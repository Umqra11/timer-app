## ✅ What Went Well

### 1. Honest pivot decision after Fix 5
The 5-fix failure threshold triggered correctly. Patron said "Duralım" rather than continuing the same approach. The Supabase attempt (commit + revert) was a legitimate exploration that informed the Cloud Functions decision.

### 2. Debug-before-fix discipline
Fix 4 (`[KronoDebug]` instrumentation) → Fix 5 (`lastRoomId` guard) is the textbook observability-first pattern. Without logs, we couldn't have distinguished "snapshot re-fire override" from other failure modes. Cleanup (Fix 6) was explicit and bundled.

### 3. M0-M6 milestone decomposition
Faz 2's M-series naming gave every commit a name and a verification step. No "fix various things" commits. When M2 had 2 sub-fixes, it was visible.

### 4. Plan + checkpoint structure
3-Part plan with `[APPROVAL NEEDED]` per part. Reusable as `[1] Part 1 deploy done. Patron tests: ...` — concrete, runnable, mechanical-engineer-friendly test scripts.

### 5. D-069 autonomous deploy
Zero "patron manual deploy" cycles in Faz 2. Sprint velocity was uninterrupted by auth/CLI gymnastics.

### 6. Race-condition awareness
M1 (250ms throttle), M2 (MAX monotonic), M3 (offline FIFO), M4 (atomic tx) — each addressed a specific race. No "fix and pray" — invariant-stated, then verified.

### 7. Polish phase explicit
M5 (unsub leak + null guards) and M6 (debug log cleanup) treated as first-class milestones, not afterthoughts. Sprint shipped clean.

## ⚠️ What Didn't / Lessons Learned

### L1. Client-side presence = architectural dead end
**Symptom:** 5 client-side fixes all failed silently. `presence.status` stayed `idle` despite `status: "running"` writes.
**Root cause:** D-015 auth-free + multi-user + `$effect` re-fire on Firestore snapshots = unfixable at the client layer.
**Lesson:** Multi-user race conditions that cross security boundaries cannot be solved client-side. Server-mediated state is the only correct primitive.
**Action:** Default to "where does this state belong?" before "where do I patch this?" for any state that crosses tabs / devices / time.

### L2. M0 setup was undercooked (3 fixes for callable invocation)
**Symptom:** `httpsCallable` invocations didn't fire (no network POST). 3 commits to wire `getFns()` correctly.
**Root cause:** Firebase SDK URL resolution wasn't tested before adding business logic.
**Lesson:** "Wire before business logic" — verify the network round-trip happens before adding rate limits, throttling, invariants. Null-data invocation is the cheapest test.
**Action:** Any future server-side work starts with a "canary call" — `onCall(handler = async () => ({ok: true}))` deployed and verified, then business logic layered.

### L3. Debug log lifecycle unclear (3 touch cycles)
**Symptom:** `[KronoDebug]` (Fix 4) → A2 telemetry → M6 comment-out. 3 commits across 2 weeks managing debug code.
**Root cause:** No convention for "log what level, ship when".
**Lesson:** Default = no log. Opt-in telemetry with TTL + feature flag.
**Action:** Define telemetry policy at Sprint-06 Faz 3 kickoff (see [[Sprint-06 roadmap]]).

### L4. Supabase pivot attempt was avoidable cost
**Symptom:** ~2 hours spent on `feat(supabase)` + revert. Zero net code change.
**Root cause:** Pivot chosen before exhausting Cloud Functions option. The "switch backend" decision was made before "can we get callable URLs to fire" was verified.
**Lesson:** Backend pivot is a 2-day decision, not a 2-hour one. Verify the current backend's wire before pivoting.
**Action:** Add "wire verification checklist" to Sprint-06 planning template.

### L5. Plan files left untracked (7 files)
**Symptom:** `docs/superpowers/plans/2026-08-12-*` never committed despite being referenced by retrospective.
**Root cause:** Sprint-Faz-1.5 pause happened before commit; subsequent M0-M6 work refocused attention.
**Lesson:** Plans are part of the audit trail. They belong in git, not in working tree.
**Action:** Commit remediation in this retro PR.

### L6. "3+ fix → question architecture" rule fired twice without short-circuit
**Symptom:** Both Faz 1.5 (fixes 1-5) and Faz 2 (M0 series 1-3) crossed the threshold. M0 series got to 3 fixes *inside* Faz 2 — same pattern emerging.
**Lesson:** Once-per-sprint is fine. Twice-per-sprint means the rule isn't biting early enough.
**Action:** Lower threshold to "2+ fix on same root cause → architectural review" for Sprint-06.
